# Image Retrieval and Licensing Research

## Purpose and Scope

This document proposes a legally conscious fallback strategy for educational
images when AI generation fails, produces an unusable result, or is unavailable.
It is research and architecture guidance only. It does not implement retrieval,
download images, or authorize reuse of any particular work.

No source below should be described as universally "copyright-free." A work may
be openly licensed, public domain, or usage-permitted subject to applicable
terms, while still carrying other legal or contractual considerations.

## Asset Categories

| Category | Meaning for this project | Required posture |
| --- | --- | --- |
| AI-generated images | Images generated by Qwen or Nano Banana from the project prompt. | Apply model terms, educational review, and project provenance rules. |
| Openly licensed images | Works offered under a specific open license, such as CC BY or CC BY-SA. | Verify the individual license and meet attribution, license-notice, and ShareAlike obligations. |
| Public-domain images | Works whose copyright is not applicable or has been waived/dedicated in the relevant context. | Verify the public-domain status and record provenance; other rights may still apply. |
| Commercial/free-stock images | Works offered under a provider's license or terms, often with restrictions. | Follow the provider's current license, API terms, and restrictions; do not treat them as an open-content dataset. |
| Arbitrary web image search | Results from general search engines, social sites, or unknown pages. | Do not use as an automated fallback: a search result does not establish reuse rights. |

## Provider Notes

### Openverse

Openverse is a search engine and API for openly licensed and public-domain
media. Its image detail metadata includes fields useful for provenance, such as
`creator`, `creator_url`, `foreign_landing_url`, `license`,
`license_version`, `license_url`, `source`, and `attribution`.

That metadata is a discovery aid, not a legal guarantee. Openverse does not
guarantee the accuracy of individual license information. Before approving a
work, inspect its source or landing page, independently verify the license,
preserve required attribution, and confirm that the intended educational use is
within the applicable terms.

### Wikimedia Commons

Wikimedia Commons licenses media on an individual-file basis. Each file
description page identifies copyright status, author information, and license
conditions. CC BY generally requires attribution and license information. CC
BY-SA also has ShareAlike implications for derivative works. Public-domain
status should be verified for the intended jurisdiction and use.

Copyright is not the only consideration. Commons explicitly notes possible
trademark, personality, privacy, moral-rights, and other non-copyright
restrictions. A file description page is therefore necessary but not, by itself,
the complete legal analysis.

### Pexels

Pexels provides a free-stock license model and an authenticated API. Its current
license permits broad commercial and non-commercial use subject to prohibited
uses. It prohibits selling or distributing content on a standalone basis, using
content as a trademark, implying endorsement, and certain harmful or misleading
uses involving recognizable people, brands, or other third-party rights.

For API use, Pexels documents a prominent provider link, photographer credit
when possible, API credentials, and request limits. This makes Pexels a possible
retrieval/display fallback after terms review, rather than a source for building
an internal image dataset or bulk archive.

### Unsplash

Unsplash provides an API and a broad image license, but API use adds operational
requirements. API clients must use the returned image URLs (hotlinking), report
download-like interactions through the documented endpoint, and attribute
Unsplash and the photographer with a link to the photographer's profile. API
quotas and access can change.

The license prohibits compiling images into a similar or competing service. Its
terms also identify separate concerns for trademarks, recognizable people, and
depicted works. Unsplash terms restrict using images in AI/ML datasets unless
separately authorized. It is therefore suitable only as a retrieval/display
fallback if its current API, attribution, hotlinking, and product terms fit the
eventual design.

## Proposed Fallback Architecture

```text
Concept / vocabulary
        |
AI generation
        |
Generation succeeds?
   +----+----+
   |         |
  YES        NO
   |         |
AI asset  Retrieval layer
              |
       Candidate images
              |
        License filter
              |
      Educational filter
              |
       Provenance record
              |
        Approved asset
```

License validation and educational suitability are separate checks. A work can
be appropriately licensed yet be a poor or unsafe educational illustration. A
visually excellent work cannot be approved without license and terms review.

### Recommended Initial Architecture

Propose, but do not implement: AI generation -> Openverse/Wikimedia fallback ->
provider-specific alternatives if needed -> validation -> provenance. The
retrieval layer should return candidates only; no candidate should be
automatically downloaded, reused, or retained as a permanent internal dataset.

Provider priority is a routing model, not a claim that any provider is legally
"best":

- Primary AI: Qwen and Nano Banana.
- Potential licensed/open-content retrieval: Openverse and Wikimedia Commons.
- Potential stock/API retrieval: Pexels and Unsplash.

Do not automatically use Google Images, Bing Images, arbitrary website
scraping, Pinterest, social-media image search, or random image URLs. General
search results do not themselves establish copyright status, licensing,
attribution requirements, or reuse rights.

## Proposed Provenance Metadata

Record provenance when a candidate is reviewed or approved:

```json
{
  "source_provider": "",
  "source_id": "",
  "image_url": "",
  "source_url": "",
  "creator": "",
  "creator_url": "",
  "title": "",
  "license": "",
  "license_version": "",
  "license_url": "",
  "attribution_required": false,
  "retrieved_at": "",
  "verification_status": ""
}
```

This metadata helps preserve provenance and audit decisions. It does not make an
image legally safe, prove title, replace individual license verification, or
clear trademarks, privacy, publicity, or personality rights.

## Educational Suitability Check

Independently review each candidate to confirm that it:

- visually represents the requested word or concept;
- is suitable for children ages 2-11;
- has no inappropriate, violent, sexual, frightening, or disturbing content;
- has no unnecessary text or visible watermark;
- avoids a misleading visual interpretation;
- has sufficient image quality;
- preferably has simple composition and a clear subject;
- avoids logos and trademarks where possible; and
- avoids identifiable people where personality, privacy, or publicity rights
  would create unnecessary risk.

Educational suitability does not replace copyright or license verification.

## Risks and Limitations

- License metadata can be wrong or outdated.
- Copyright status can differ by jurisdiction.
- Trademarks, personality rights, privacy rights, and moral rights may exist
  independently of copyright.
- API and provider terms can change.
- Provider-specific attribution requirements must be preserved.
- Retrieved images should not automatically become a permanent internal dataset.
- Production or commercial use requires review of applicable provider terms.

## Step 4 Conclusion

The project should investigate license-aware image retrieval as a fallback, but
should not implement automatic downloading or reuse until provider-specific
terms, metadata handling, and validation rules are defined.
